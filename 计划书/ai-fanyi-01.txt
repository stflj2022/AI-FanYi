01

好。现在正式进入 **MODULE 01 -- Project & Media Intake（项目与媒体输入模块）**。

这一模块我们先**不碰人物识别、不碰 ASR、不碰 TTS、不碰联网研究**。它只有一个职责：

**把用户交给系统的一部影视文件，安全、完整、可追踪地登记成一个标准化 Project，并生成后续所有模块都能使用的 Media Manifest。**

这一模块完成后，后面的任何模块都不应该再直接"猜测"原始视频是什么，而是统一读取本模块产生的标准数据。

我会按真正可开发的工程来设计。

# **1. 本模块的边界**

必须先把边界定死。

## **本模块负责**

- 上传视频
- 导入本地视频
- 文件完整性检查
- SHA-256
- 文件大小
- 文件格式
- 视频流
- 音频流
- 字幕流
- 字幕轨道
- 章节
- metadata
- 时长
- 分辨率
- FPS
- 音频采样率
- 声道
- 原始语言信息
- 创建 Project
- 创建 Episode
- 建立数据库
- 建立任务状态
- 生成标准 manifest
- 记录日志

## **本模块不负责**

- 搜索 IMDb/TMDB
- 识别演员

- Whisper
- Speaker Diarization
- 翻译
- TTS
- 音源分离
- 混音
- 视频重新编码

这几个边界一定不能混。

# **2. 为什么第一模块必须这么"笨"**

例如用户上传：
    
    
    Breaking.Bad.S01E01.1080p.WEB-DL.DD5.1.H.264.mkv

我们不能让后面的 Character Worker 自己再去：
    
    
    猜这是 Breaking Bad
    猜这是第一季
    猜这是第一集
    猜视频时长
    猜哪个音轨是英文
    猜哪个字幕是中文

这些信息必须在 Module 01 就固定下来。

因此以后所有模块只认：
    
    
    project_id
    episode_id
    media_id

# **3. 三个核心 ID**

这是整个系统非常重要的设计。

## **Project ID**

代表整部影视作品。

例如：
    
    
    bb

或者：
    
    
    breaking_bad

但我建议使用不可变 UUID：
    
    
    proj_01JXXXXXXXXXXXX

* * *

## **Episode ID**

代表某一集：
    
    
    ep_01JXXXXXXXXXXXX

例如：
    
    
    Breaking Bad
    Season 1
    Episode 1

* * *

## **Media ID**

代表具体文件。

因为同一集可能有：
    
    
    1080p WEB-DL
    1080p BluRay
    2160p WEB-DL

所以：
    
    
    Project
       │
       └── Episode
             │
             ├── Media A
             ├── Media B
             └── Media C

非常重要。

* * *

这样以后可以：

# **10. 原始文件是 Immutable Asset**

这是专业系统必须遵守的规则。

上传：
    
    
    original.mkv

之后任何模块都不能修改它。

不能：
    
    
    FFmpeg → original.mkv

必须：
    
    
    original.mkv
          ↓
    derived/

例如：
    
    
    audio/source.wav

由原始视频派生。

这样任何一步失败，都可以从原始文件重新开始。

# **11. 文件 Hash**

上传后首先：
    
    
    SHA-256

例如：
    
    
    sha256:
    8f3b7c....

数据库：
    
    
    media.sha256

作用：

### **① 防止重复导入**

用户再次上传同一个文件：
    
    
    SHA256相同

系统告诉：

这个文件已经存在。

### **② 数据完整性**

后面任何时候可以验证：
    
    
    original.mkv
    SHA256

是否发生改变。

# **12. 文件名解析**

我们建立：
    
    
    Filename Parser

例如：
    
    
    Breaking.Bad.S01E01.1080p.WEB-DL.mkv

得到：
    
    
    {
      "title_candidate": "Breaking Bad",
      "season": 1,
      "episode": 1,
      "quality": "1080p",
      "source": "WEB-DL"
    }

但这里有一个重要原则：

**文件名解析只能产生 Candidate，不是最终事实。**

因为：
    
    
    Some.Show.1x01.mkv

也可能存在。

所以：
    
    
    filename parser
           ↓
    candidate
           ↓
    Module 02 Research
           ↓
    最终确认

# **16. 为什么必须记录所有音轨**

不能只记录：
    
    
    第一条音轨

因为影视文件可能：
    
    
    Audio 1 English 5.1
    Audio 2 English Stereo
    Audio 3 Commentary
    Audio 4 Japanese

后面 Source Separation 模块需要知道：

哪一条才是目标原始对白音轨。

所以全部记录。

* * *

# **17. Subtitle Stream**

同样：
    
    
    {
      "index": 4,
    
      "codec": "subrip",
    
      "language": "chi",
    
      "title": "Chinese Simplified",
    
      "default": false,
    
      "forced": false
    }

以后 Subtitle Worker 可以直接看到：
    
    
    有中文字幕

从而：

**跳过翻译。**

这正好符合我们之前确定的策略。

# **35. 非常重要：上传不能直接写入最终路径**

必须：
    
    
    /tmp/upload/uuid.tmp

检查成功：
    
    
    /tmp/upload/uuid.tmp
            ↓

检查失败：
    
    
    删除 tmp

# **36. 文件上传 API 不应该负责重处理**

上传接口：
    
    
    HTTP 202 Accepted

然后：
    
    
    Media Intake Job

后台运行。

FastAPI 官方的 BackgroundTasks 可以处理简单的后台任务；但官方也明确指出，对于重计算、跨进程/服务器的任务，更适合 Celery 等独立任务系统。我们的影视处理显然属于后者，因此这里应该把真正的 Worker 与 API 进程分离。

# **37. GPU 不属于 Module 01**

虽然最终工程使用 NVIDIA GPU，但：

Module 01 不需要 CUDA。

因此：
    
    
    api container
    CPU
    
    media-intake worker
    CPU

后面的：
    
    
    diarization
    TTS
    separation

才申请 GPU。

这也是模块隔离的重要体现。

# **58. probe.py**

核心：
    
    
    import json
    import subprocess
    from pathlib import Path
    
    
    def ffprobe(path: Path) -> dict:
        cmd = [
            "ffprobe",
            "-v", "error",
            "-print_format", "json",
            "-show_format",
            "-show_streams",
            "-show_chapters",
            str(path),
        ]
    
        result = subprocess.run(
            cmd,
            capture_output=True,
            text=True,
            check=True,
        )
    
        return json.loads(result.stdout)

这是故意保持简单。

FFprobe 自身已经负责媒体解析，不需要我们重新造一个媒体解析器。

* * *

# **59. hashing.py**
    
    
    import hashlib
    from pathlib import Path
    
    
    def sha256_file(
        path: Path,
        chunk_size: int = 8 * 1024 * 1024,
    ) -> str:
    
        digest = hashlib.sha256()
    
        with path.open("rb") as f:
            while chunk := f.read(chunk_size):
                digest.update(chunk)
    
        return digest.hexdigest()

8 MB chunk 足够。
