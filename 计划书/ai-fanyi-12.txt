# **MODULE 12 -- Project QA & Human Review**

## **12.00 模块定位**

MODULE 12 是整个系统的**质量控制与人工审核层**。

它不重新制作内容，只负责：
    
    
    MODULE 01--11 的全部产物
                ↓
          自动质量检查
                ↓
           问题分类/评分
                ↓
           人工审核队列
                ↓
          返回指定模块重做
                ↓
             最终批准

核心原则：

**发现问题只回退到产生问题的模块，绝不整条流水线重跑。**

# **12.02 QA 的核心不是"给整集打分"**

错误设计：
    
    
    S01E01
    Quality = 87%

这个数字没有实际意义。

真正需要知道的是：
    
    
    S01E01
    │
    ├── Scene 001 ✓
    ├── Scene 002 ✓
    ├── Scene 003 ⚠
    │      └── dlg_184
    │
    ├── Scene 004 ✓
    ├── Scene 005 ⚠
    │      ├── voice mismatch
    │      └── timing
    │
    └── Scene 006 ✓

所以：

**QA 的最小单位是 Dialogue / Scene，而不是 Episode。**

# **12.09 Clipping**

检测：
    
    
    sample > 0 dBFS

或者：
    
    
    True Peak > threshold

如果：
    
    
    clipping = true

自动：
    
    
    FAIL

回退：
    
    
    MODULE 10

而不是重新生成 TTS。

# **12.12 Voice Similarity**

数据库保存：
    
    
    {
      "character": "Walter",
      "voice_embedding": "...",
      "reference_segments": 37
    }

当前对白：
    
    
    dlg_184.wav

    cosine_similarity

例如：
    
    
    Walter
    0.94 ✓
    
    Jesse
    0.61
    
    Hank
    0.48

判定：
    
    
    PASS

* * *

# **12.13 相似度阈值**

不要设计成：
    
    
    similarity > 0.90 = PASS

这么简单。

因为：
    
    
    愤怒
    耳语
    哭泣
    喊叫
    电话
    远距离

都会改变 embedding。

应该：
    
    
    Character-specific threshold
    +
    Emotion-aware threshold
    +
    Scene-aware threshold

* * *

      "status": "PASS"
    }

# **12.20 Overlap QA**

检测：
    
    
    A:
    00:01:20--00:01:23

    00:01:22--00:01:25

    A:
    00:01:20--00:01:25

    00:01:22--00:01:25

    ⚠ excessive overlap

# **12.23 不要简单平均**

例如：
    
    
    Voice = 100
    Translation = 100
    Timing = 100
    Mix = 40

    85

却可能非常难听。

所以：
    
    
    Critical Failure

拥有最高优先级。

    Clipping
    Voice mismatch
    Missing dialogue
    Severe sync error

    Scene = FAIL

# **12.42 12.14 "父母满意度"指标**

你的最终目标不是：

AI Benchmark 第一。

而是：

**父母能不能舒服地看完整部美剧。**

因此增加一个特殊指标：
    
    
    Parent Viewing Score

但它不由 AI 自动决定。

由人工体验评价：
    
    
    声音是否自然
    人物是否容易区分
    台词是否听得清
    有没有明显 AI 感
    音乐是否正常
    剧情是否连贯

# **12.59 最终设计原则**

这个模块最终必须做到五件事：
    
    
    ① 自动发现问题
    
    ② 准确定位问题
    
    ③ 找到问题来源模块
    
    ④ 只重新处理有问题的部分
    
    ⑤ 人工批准后才能成为最终版本

最终形成：
    
    
                    ┌───────────────┐
                    │   MODULE 12   │
                    │      QA       │
                    └───────┬───────┘
                            │
              ┌─────────────┼─────────────┐
              ↓             ↓             ↓
           PASS          REVIEW          FAIL
              │             │             │
              │             ↓             ↓
              │        Human Review   Root Cause
              │             │             │
              │        ┌────┴────┐         │
              │        ↓         ↓         │
              │     APPROVE    REWORK      │
              │                  │         │
              │                  └────┬────┘
              │                       ↓
              │                指定 MODULE
              │                       ↓
              └─────────────────── QA
                                      ↓
                                  APPROVED

**MODULE 12 完成后，系统已经具备"生产--检测--局部返工--再检测--批准"的闭环。**

下一模块 **MODULE 13 -- Batch / Season Pipeline** 将把现在的"**一集一集处理**"升级成真正的"**整季/整部剧流水线**"：任务队列、GPU/CPU 资源调度、断点续跑、失败重试、并行与串行策略、跨集共享人物数据库，以及最重要的**某一集失败不会影响其他集继续生产**。
