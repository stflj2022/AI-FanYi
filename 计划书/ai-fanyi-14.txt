## **项目档案、版本控制、长期保存与完整复现系统**

* * *

# **14.00 模块定位**

MODULE 14 负责解决一个核心问题：

**几年以后，能否拿着这个项目档案，在另一台有 NVIDIA GPU 的机器上，把当年的成片完整复现出来？**

必须保存的不只是最终 MP4，而是：
    
    
    原始视频
    +
    字幕
    +
    人物数据库
    +
    人物音色
    +
    翻译记忆
    +
    剧情上下文
    +
    所有模型
    +
    模型版本
    +
    Prompt
    +
    参数
    +
    Module版本
    +
    Artifact
    +
    QA结果
    +
    人工修改
    +
    最终成片

目标：
    
    
    REPRODUCIBLE
    可复现
    
    PORTABLE
    可迁移
    
    AUDITABLE
    可追溯
    
    IMMUTABLE
    历史版本不可被偷偷修改

# **14.11 SHA-256**

每个重要文件计算：
    
    
    SHA256

例如：
    
    
    source.mp4
    → 91f3....
    
    audio.wav
    → 3a17....
    
    final.mp4
    → 8bd2....

以后任何文件发生变化：
    
    
    hash ≠ 原 hash

系统立即知道。

* * *

# **14.12 为什么不能只保存文件名**

错误：
    
    
    final.mp4

正确：
    
    
    final.mp4
    SHA256:
    8bd2...

这样可以证明：

这是当时生成的那个文件。

* * *

# **14.13 Immutable Artifact**

生产完成后：
    
    
    Artifact

默认：
    
    
    READ ONLY

修改不能覆盖原文件。

必须：
    
    
    v001
    v002
    v003

* * *

# **14.14 禁止这种操作**
    
    
    audio.wav

直接覆盖：
    
    
    audio.wav

必须：
    
    
    audio/
    ├── v001.wav
    ├── v002.wav
    └── v003.wav

# **14.20 14.01 Memory Snapshot**

每集开始生产时生成：
    
    
    MEMORY SNAPSHOT

例如：
    
    
    S01E05
    使用：
    
    Character DB = V03
    Voice DB     = V05
    Glossary     = V04
    Story Bible  = V03
    TM           = V07

这样几年以后可以准确知道：

E05 当时使用的是哪套记忆。

* * *

# **14.21 为什么必须 Snapshot**

假设：
    
    
    E01
    使用 Memory V02

后来：
    
    
    Memory V05

如果没有 Snapshot：
    
    
    重新生产 E01

就可能得到不同结果。

有 Snapshot：
    
    
    E01 → Memory V02

结果可以复现。

* * *

    TTS Engine

    v1.2
