# **MODULE 13 -- Batch / Season Pipeline**

## **13.00 模块定位**

MODULE 13 将前面的：

**"一集影视剧 AI 中文配音系统"**

升级为：

**"整季 / 整部影视剧自动化生产系统"。**

核心目标：
    
    
    S01E01 ──→ 独立生产
    S01E02 ──→ 独立生产
    S01E03 ──→ 独立生产
    S01E04 ──→ 独立生产
    ...

任何一集失败：
    
    
    S01E03 = FAILED

不影响：
    
    
    S01E01 = DONE
    S01E02 = DONE
    S01E04 = PROCESSING
    S01E05 = PROCESSING

# **13.08 为什么必须"双层状态"**

不能只记录：
    
    
    Episode = RUNNING

因为不知道：
    
    
    当前正在运行 MODULE 09

还是：
    
    
    MODULE 09 已完成
    MODULE 10 正在运行

所以：
    
    
    Episode State
    +
    Module State

必须同时存在。

核心组件：
    
    
    Job Queue

推荐设计：
    
    
    Redis
    +
    PostgreSQL

其中：
    
    
    Redis

负责：
    
    
    实时队列
    worker调度
    锁
    heartbeat

PostgreSQL：
    
    
    永久状态
    任务历史
    版本
    QA

# **13.10 不让 Redis 成为唯一数据库**

错误：
    
    
    所有状态 → Redis

    整个项目状态丢失

正确：
    
    
    PostgreSQL
       ↑
    永久真相源
    
    Redis
       ↑
    临时任务队列

# **13.11 13.02 Worker**

每个 Worker 是：
    
    
    独立进程

负责：
    
    
    领取一个 Job
     ↓

     ↓

     ↓

# **13.43 13.13 GPU 显存隔离**

# **13.44 13.14 OOM Recovery**

如果运行过程中：
    
    
    CUDA OOM

Worker：
    
    
    terminate

释放：
    
    
    GPU memory

然后：
    
    
    retry

可自动降低：
    
    
    batch size

例如：
    
    
    16
     ↓
    8
     ↓
    4
     ↓
    2

* * *

# **13.45 但不要无限自动降低**

否则：
    
    
    batch = 1

还在跑几个小时。

所以：
    
    
    min_batch = 2

仍然失败：
    
    
    FAILED

进入人工处理。

* * *

# **13.46 13.15 Episode 并行度**

默认：
    
    
    重型 GPU 模块
    parallel = GPU count

轻量模块：
    
    
    CPU parallel = CPU cores / 2

但最终由资源调度器动态决定。

    GPU 限制

因此：

**并行策略属于 Module，而不是整个系统统一设置。**

# **13.56 13.20 原子提交**

Worker 完成 Artifact：

不能直接写：
    
    
    final.wav

而应该：
    
    
    temp.wav

完成后：
    
    
    SHA256
     ↓
    rename
     ↓
    register DB

这样服务器突然断电不会得到：
    
    
    半个 WAV

却被系统误认为成功。

例如：
    
    
    E03 MODULE 09

防止：
    
    
    Worker A
    +
    Worker B

# **13.58 13.22 Idempotency**

同一个 Job 执行两次：
    
    
    结果应该一致

或者：
    
    
    旧 Artifact
    +
    新 Artifact

不会破坏项目。

这要求每次执行都具有：
    
    
    Run ID
    Artifact ID
    Version
