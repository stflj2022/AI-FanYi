# **影视 AI 配音平台**

# **Layer 0 最终工程方案 V1.0**

**正式基线：Layer 0 = Workflow Orchestrator**

核心原则：**M01--M14 负责具体能力，Layer 0 负责判断、编排、调度、缓存、资源管理和恢复。**

不人为枚举所有排列组合，而是通过 **Task Context → Asset Discovery → Capability Matrix → Workflow Selector → Dependency Resolver → Workflow Planner → Executor** 动态生成当前任务的最小必要执行链。

# **二、Layer 0 的职责边界**

## **Layer 0 做什么**
    
    
    判断任务
    发现资产
    选择 Workflow
    解析依赖
    生成执行计划
    调度 Module
    管理资源
    管理 Artifact
    管理状态
    失败恢复
    断点续跑
    缓存复用

## **Layer 0 不做什么**
    
    
    不进行 ASR
    不进行翻译
    不进行 TTS
    不做人声克隆
    不做混音
    不做视频编码

这些全部属于 M01--M14。

* * *

# **三、M01--M14 的定位**

Layer 0 不关心某个模块内部使用什么模型。

例如：
    
    
    M06 = Translation
    M09 = TTS / Voice Generation
    M10 = Prosody / Voice Processing

M09 今天可以使用：
    
    
    CosyVoice

以后换成：
    
    
    F5-TTS
    某个更好的模型

Layer 0 无需修改。

# **六、Capability Matrix**

这是最终方案的核心。

每种资源都不是简单：
    
    
    有 / 无

而是：
    
    
    NONE
    PARTIAL
    COMPLETE
    INVALID
    OUTDATED

例如人物库：
    
    
    NONE       0%
    PARTIAL    60%
    COMPLETE   100%
    INVALID
    OUTDATED

声音库同理。

    声音库完整

### **项目**
    
    
    首次处理
    已有项目

### **Artifact**
    
    
    不存在

### **用户要求**
    
    
    Quick

### **任务类型**
    
    
    Preview

# **八、为什么不手工写所有组合**

假设：
    
    
    视频长度       2
    字幕           2
    人物库         3
    声音库         3
    首次处理       2
    质量要求       3

已经有：
    
    
    2 × 2 × 3 × 3 × 2 × 3 = 216

种组合。

再加入：
    
    
    字幕质量
    人物覆盖率
    声音覆盖率
    Artifact
    项目状态

组合会迅速爆炸。

因此最终设计：

**不枚举组合，而是描述状态 + 描述依赖 + 动态生成执行图。**

# **九、L0-03 Workflow Selector**

Selector 只负责选择：
    
    
    QUICK
    STANDARD
    PRODUCTION

* * *

## **QUICK**

适合：
    
    
    短视频
    ≤20分钟片段
    试听
    模型测试
    快速观看

典型目标：

**最快得到可接受结果。**

* * *

## **STANDARD**

适合：
    
    
    单集电视剧
    普通电影
    正式观看

目标：

**质量 / 时间 / GPU 成本平衡。**

* * *

## **PRODUCTION**

适合：
    
    
    整部电影
    整季电视剧
    完整项目
    长期保存
    高质量制作

目标：

**建立完整、稳定、可复用资产。**

* * *

# **十、Selector 的决策原则**

优先级：
    
    
    用户明确要求
          ↓
    任务类型
          ↓
    已有资产
          ↓
    资产质量
          ↓
    字幕状态
          ↓
    视频长度

所以：
    
    
    10分钟 + 用户要求 Production

仍然可以：
    
    
    PRODUCTION

而：
    
    
    60分钟 + 已有全部资产 + 只是试听

可以：
    
    
    QUICK

* * *

# **十一、第一版不使用 LLM 决策**

Workflow Selector 使用：
    
    
    Rule Engine
    +
    Scoring
    +
    Hard Constraints

而不是让 Qwen 自己决定。

这样：
    
    
    输入相同
    → 决策相同

便于测试、调试和长期维护。

* * *

# **十二、L0-04 Dependency Resolver**

Selector 选择 Workflow 后，Resolver 开始检查：

**这条工作流真正需要哪些前置条件？**

例如：
    
    
    M09 TTS

依赖：
    
    
    M07 Speaker Mapping
    M08 Dialogue Preparation
    Voice Profile

如果 Voice Profile 不存在：
    
    
    M04

自动成为前置任务。

# **四十、最终工程原则**

整个 Layer 0 最终遵守 **10 条原则**：

### **① 模块独立**

M01--M14 互不直接调用。

### **② Layer 0 统一调度**

所有模块通过 Layer 0 协调。

### **③ 不强制跑完整流程**

只执行当前任务需要的模块。

### **④ 不靠人工枚举组合**

使用：
    
    
    Capability Matrix
    +
    Dependency Graph
    +
    Rule Engine

动态生成。

### **⑤ 支持增量处理**

人物库、声音库等可以局部更新。

### **⑥ 支持缓存**

已有 Artifact 不重复计算。

### **⑦ 模块串行、资源释放**

一个模块完成后释放 GPU / RAM。

### **⑧ 失败可恢复**

从失败模块继续。

### **⑨ 模型可替换**

Layer 0 不绑定具体 AI 模型。

### **⑩ 用户拥有最终决定权**

自动选择可以被用户覆盖。
