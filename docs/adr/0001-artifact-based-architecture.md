# ADR 0001: 基于 Artifact 的模块架构

## 状态

已采纳

## 上下文

影视AI配音平台包含 14 个生产模块 (M01-M14) 和一个 Layer 0 编排层。模块之间需要传递大量数据：视频、音频、字幕、人物信息、对白时间轴等。

需要确定模块之间的交互方式。

## 决策

采用 **基于 Artifact 的架构**：

- 模块之间不直接互相调用
- 每个模块从 Artifact Registry 读取输入 Artifact
- 每个模块处理后，将输出写入 Artifact Registry
- Layer 0 负责协调和调度

## 替代方案

### 方案 A: 直接函数调用
模块 A 直接调用模块 B 的函数。

**优点**:
- 简单直接
- 性能开销小

**缺点**:
- 强耦合，难以替换模块实现
- 难以并行执行
- 难以实现断点恢复
- 难以跨语言/跨服务

### 方案 B: 消息队列
模块之间通过消息队列传递数据。

**优点**:
- 解耦
- 易于扩展

**缺点**:
- 对于大型二进制数据（视频、音频）不合适
- 增加系统复杂度
- 调试困难

## 后果

### 正面

1. **模块可替换性**: M09 可以从 CosyVoice 切换到 F5-TTS，不影响其他模块
2. **并行执行**: M02 和 M05 可以同时运行
3. **断点恢复**: 系统崩溃后可以从任意 Artifact 恢复
4. **跨语言**: Layer 0 用 Python，M09 可以用任何语言
5. **可测试性**: 每个 Module 可以独立测试
6. **审计追踪**: 所有 Artifact 都有版本历史

### 负面

1. **存储开销**: 需要维护 Artifact Registry
2. **I/O 开销**: 数据读写比直接调用慢
3. **初始复杂度**: 需要设计和实现 Artifact Registry

### 缓解措施

- 使用 MinIO 或类似存储服务优化大型 Artifact 存储
- Artifact Registry 支持缓存和引用计数
- 对于小型数据（如 JSON 配置），可以内存缓存
